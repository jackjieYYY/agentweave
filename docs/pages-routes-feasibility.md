# AgentWeave 页面与路由实施方案

## 1. 首期范围

**首期交付 6 个业务页面与 1 个 404 页面，共 7 页。** 完成注册、登录、模型配置、新建会话、聊天、工具审批、恢复执行与本地退出的闭环。邮箱、主题切换和退出统一放在用户菜单中。

目标使用场景为受信任成员使用的共享工作台，后端按单实例部署。会话按用户隔离，Provider 与模型配置由所有认证用户共享；开放注册的公网多租户产品需要先交付配置归属与后端授权。

实现复用当前基础：

- React Router 组织路由；TanStack Query 管理服务端数据；现有 store 管理身份和主题偏好。
- [API 封装](../src/api/endpoints.ts)、[查询与 mutation](../src/api/queries.ts)、[执行流消费](../src/api/execution.ts)负责请求、缓存刷新与 SSE 解析。
- [认证操作](../src/auth/session.ts)负责登录、身份恢复和本地退出。
- UI 按需使用 shadcn 组件，沿用官方 Neutral 浅色／深色及独立的 Perplexity 配色，通过[语义变量](../src/index.css)提供颜色。

业务合同以 [API 交接文档](../frontend-api-handoff.md)为准，调用方式见 [API 接入说明](./api-client.md)。本方案定义页面职责与交互约束。

## 2. 页面与路由

| 页面          | 路由                                 | 访问条件         | 主要职责                                               |
| ------------- | ------------------------------------ | ---------------- | ------------------------------------------------------ |
| 登录          | `/login`                             | 公开             | 邮箱、密码、错误提示、登录后返回原入口                 |
| 注册          | `/register`                          | 公开             | 注册并登录，处理注册成功但登录失败                     |
| 会话工作台    | `/app/conversations`                 | 已认证           | 分页历史、新建入口、关闭标记、配置引导                 |
| 聊天          | `/app/conversations/:conversationId` | 已认证且有权访问 | 历史、模型选择、输入、执行预览、审批、继续、停止、关闭 |
| Provider 配置 | `/app/settings/providers`            | 已认证           | 列表、创建、编辑、替换 Key、启用／停用                 |
| 模型配置      | `/app/settings/models`               | 已认证           | 列表、创建、编辑、启用／停用                           |
| 页面不存在    | `*`                                  | 公开             | 未知路径提示与返回入口                                 |

同一路由下不同 ID 共用一个页面模板。弹窗、菜单、错误状态和布局由所属页面承载。

```text
/                                      按认证状态重定向
/login                                 登录
/register                              注册
/app                                   认证守卫 + AppLayout
  (index)                              重定向到 conversations
  /conversations                       会话工作台
  /conversations/:conversationId       聊天
  /settings                            共用设置导航
    (index)                            重定向到 providers
    /providers                         Provider 配置
    /models                            模型配置
*                                      404
```

登录与注册共用表单外壳；AppLayout 承载导航和用户菜单。`/` 在身份确认后，匿名转 `/login`，已认证转 `/app/conversations`；`/app` 与 `/app/settings` 的重定向均经过认证守卫。已认证用户访问登录或注册页时转工作台。

### 2.1 认证与 URL 规则

- `unverified`、`restoring` 期间显示身份确认状态；身份确认后再请求受保护数据。恢复失败且并非 401 时保留 Token，显示重试入口。
- 登录返回地址只接受站内已知的 `/app` 路径。受保护请求的 401 清理身份并转登录；登录接口的 401 在表单中展示。
- 非法会话 ID 和详情接口的 404 在聊天页内显示“会话不存在或不可访问”，保留导航。
- 分页由现有 infinite query 管理；搜索、状态筛选和排序需要对应 API 合同后再接入。
- 移动端共用路由，侧栏收起，设置导航适应窄屏。

## 3. 页面行为

### 3.1 登录与注册

使用现有注册 API 与 `sessionActions.login`。注册成功后调用登录；第二步失败时展示已注册事实并提供登录入口，避免再次提交注册。

密码按合同保留原样，长度为 15–128 个 Unicode 码点。Token 有效期 7 天，保存于 sessionStorage；登录页说明到期需重新登录。本地退出清除当前客户端身份与缓存，不能使其他设备持有的 Token 失效。

### 3.2 会话工作台

- 列表复用游标分页，显示“会话 + 短 ID”、创建时间、关闭状态和可解析的最近执行模型。顺序为创建时间倒序。
- 列表缺少标题、摘要和执行状态，按实际字段展示；每条记录直接使用列表数据。
- 新建按钮在请求期间禁用，一次创建成功后进入详情。打开工作台时只查询列表。
- 创建结果未知时刷新列表辅助核对，提示用户确认后再决定是否新建。当前没有幂等标识，不能自动识别候选记录或自动重发创建请求。
- 无可用模型时提供配置入口；Provider 保存后可进入模型页完成配置。

### 3.3 聊天与执行

持久化历史使用详情中的 `messages`。SSE 文本仅作为本次执行预览；执行结束后以详情重建历史。执行结果按返回的终态展示，HTTP 200 不等于执行成功。模型选择保留在聊天页本地状态，每次新输入明确提交 `modelConfigId`，使用前校验模型及 Provider 均启用。

**发送、继续与审批共用页面内互斥规则，按钮和提交入口均须遵守：**

| 状态或条件                                         | 操作规则                                                             |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| `closedAt !== null`                                | 只读历史，提供新建入口                                               |
| 任一发送、继续、审批或关闭 mutation 为 `isPending` | 立即禁用发送、继续与审批                                             |
| 写请求结束，正在确认详情或确认查询失败             | 保持禁用发送、继续与审批，查询失败时提供重试入口                     |
| 服务端 `active: true`                              | 禁用发送、继续与审批，等待执行或收尾                                 |
| 状态已确认，`canSubmit` 且选中可用模型             | 允许发送新消息                                                       |
| 状态已确认，`canContinue`                          | 允许继续，沿用服务端最近执行模型，不重复发送文本或模型 ID            |
| 状态已确认，`canApprove` 且目标审批为 `pending`    | 按 `allowedDecisions` 选择决策，按 actions 原顺序提交                |
| 审批为 `unconfirmed`                               | 显示结果未确认，禁止重发该决策或用 continue 绕过，提供关闭并新建入口 |

关闭、本地请求和待确认状态优先于服务端可操作字段。现有 mutation 在请求结束后刷新详情；请求开始时的缓存可能仍为 `active: false`，页面通过本地 `isPending` 立即互斥。

执行恢复统一遵守以下规则：

1. 进入或返回聊天页时先查询详情再开放操作。执行正常结束、失败或中止后均重新查询详情；写请求结束后的详情查询成功前保持待确认。查询失败时保留该状态，不能凭旧缓存解锁。
2. 断网、缺少 end 或执行写请求 5xx 时，只查询详情确认结果。409 同样刷新详情；写请求由用户在状态确认后决定是否再次发起。
3. 审批结果未知后，若详情仍 active 则等待；若恢复为 pending，则由用户确认后提交；若为 unconfirmed，则保持禁止重发。
4. `active: true` 时复用现有每秒轮询，直至收尾完成。本地请求互斥与服务端并发校验共同生效，提交时仍需处理 409。

首期执行请求与预览随聊天页管理：**切换会话或离开聊天页时中止当前 fetch，返回时查询详情恢复。** 执行期间明确提示离开会请求停止生成，已保存内容以详情为准。

| 用户操作     | 实现与结果                                                                         |
| ------------ | ---------------------------------------------------------------------------------- |
| 停止本次生成 | 中止当前页面持有的 fetch，触发协作停止，再查询详情；会话保留，预览文本可能尚未保存 |
| 关闭会话     | 调用 `/conversations/:conversationId/cancel`，永久只读，并请求停止在途执行         |

本地请求期间仍可停止当前流或关闭会话；关闭请求本身禁止重复提交。关闭前明确告知不可重新打开，响应仍 active 时继续等待收尾。拒绝工具请求只作用于该次审批，Agent 后续可能再次申请审批。

工具事件只展示请求或结束提示，审批摘要仅作为有限展示信息；工具结束事件与审批审计均不能证明工具执行成功。

### 3.4 Provider 与模型配置

两个列表页共用设置导航，创建与编辑使用页内 Dialog，保存后复用现有 mutation 刷新配置和相关会话查询。表单遵循交接合同的严格字段校验。

- 标注配置由所有认证用户共享，编辑与停用会影响其他用户后续执行。
- Key 仅用于新增或替换，不回填，不进入 URL、持久化状态、日志或错误上报；保存成功或关闭表单后清空。
- 编辑未修改 Key 时省略 `apiKey`；PATCH 只包含允许字段且不能为空。
- `openai-compatible` 必填符合合同的 HTTPS 地址；修改 Provider type 时按需要同时提交地址。
- 模型创建时关联 Provider，编辑只接受 `modelName` 与 `enabled`。名称不保证唯一，列表、选择器与缓存均以 ID 标识。
- 聊天模型选项按 `enabled && providerEnabled` 筛选。配置启用与保存成功均不代表上游模型可用。
- 当前通过启用／停用管理可用性，删除与连接测试需要对应后端能力。

## 4. 实现职责

页面按登录、注册、会话工作台、聊天和两个配置页组织，共用现有 404。业务组件在实际复用时提取，表单与执行预览留在所属页面。

| 数据或状态                                 | 归属                          |
| ------------------------------------------ | ----------------------------- |
| 会话列表、详情、模型与 Provider            | 现有 TanStack Query 缓存      |
| 登录身份、恢复错误与认证请求取消           | 现有 session store 与认证操作 |
| 主题偏好                                   | 现有 preferences store        |
| 表单、当前模型选择、流预览与结果待确认状态 | 所属页面                      |
| 写请求是否进行中                           | 现有 mutation 状态            |

聊天页复用 API、查询选项与执行流解析，服务端可操作字段控制业务准入。当前页面状态足以承载首期执行生命周期。

## 5. 部署与核心验收

### 5.1 部署条件

| 项目       | 条件                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 浏览器接入 | 生产同源代理将 `/api/*` 去掉前缀后转发后端；后端当前无 CORS                      |
| SPA 深链   | 应用路径回退 index.html，`/api/*` 保留 API 响应                                  |
| SSE        | 关闭代理缓冲，读超时结合实际执行时长并留出收尾余量；流无心跳，短暂静默不等于失败 |
| 执行协调   | 首期单实例；多实例需要后端共享执行准入与取消协调                                 |
| 权限       | 会话按用户隔离，配置全局共享，使用范围限定为受信任成员                           |
| 健康检查   | `/health` 可用于部署探针，只证明数据库连通                                       |

消息当前一次性返回，缺少稳定消息 ID、逐消息时间和分页。首期提供基础历史展示，长会话能力按使用反馈与后端合同迭代。

### 5.2 验收路径

1. 注册后登录、刷新恢复身份；401 与服务故障分开处理，退出或切换账号清空旧缓存。
2. Provider 与模型创建编辑符合字段约束，Key 不回显，停用影响模型选择器。
3. 创建会话、发送中文并展示流预览；请求开始即禁止重复发送、继续与审批，结束并确认详情后恢复可操作项。
4. 按 actions 顺序 approve／reject；断网与 unconfirmed 不自动重发，状态确认失败时保持待确认并可重试查询。
5. 停止、切换会话与返回后按详情恢复；关闭后只读；409 后刷新，另一用户的会话不可访问。
6. 生产代理下验证深链刷新、SSE 持续传输与执行收尾。

自动化覆盖认证隔离、执行互斥与恢复、审批等核心分支；表单、导航和响应式通过浏览器联调验证，遵循仓库测试范围与覆盖率约束。

## 6. 交付顺序与估算

1. **可登录、可配置：** 路由、认证守卫、用户菜单、登录注册、Provider 与模型管理，跑通首次配置。
2. **可对话、可恢复：** 会话工作台与聊天，连同请求互斥、审批、停止、继续、关闭和未知结果确认一起交付。
3. **可验收：** 验证核心路径、窄屏布局和生产代理，确认刷新、冲突与异常恢复行为。

按一名熟悉现有栈的前端工程师、采用现有视觉基准、API 按合同可用估算，首期约 **10–15 人日**，包含核心联调，不含后端新增能力。聊天状态、审批恢复与代理环境是主要工期变量，日历周期取决于联调反馈。

## 7. 后续能力的独立触发条件

各项能力分别按实际需求立项，先确定最小合同，再决定页面或页内入口。

| 能力         | 触发条件                                     | 最小前置能力与承载方式                                           |
| ------------ | -------------------------------------------- | ---------------------------------------------------------------- |
| 会话易用性   | 标题、搜索、最近活跃排序或长历史成为日常需求 | 后端补字段、查询或消息分页，复用工作台与聊天页                   |
| 审批收件箱   | 用户需要跨会话集中处理审批                   | 按授权范围聚合待审批项并稳定定位，提供单独入口，复用聊天审批规则 |
| 执行追踪     | 用户需要回看某次执行与工具步骤               | 独立执行标识、持久记录与查询接口，按浏览需求组织列表和详情       |
| Agent 配置   | 任务确实需要不同指令、默认模型或工具组合     | 后端持久配置、校验与执行绑定，先以列表和表单承载                 |
| 工具配置     | 工具需要独立凭证、参数或权限管理             | 后端目录、凭证保管与授权，简单配置先用列表与 Dialog              |
| 后台持续执行 | 需要离开页面后持续运行或跨客户端接收状态     | 后端持久执行生命周期与状态同步，前端再调整请求及预览归属         |

审批收件箱可独立交付。执行追踪中的持久执行标识由后端提供，`requestId` 仅用于排障，现有 SSE 信息不足以重建可信的历史执行轨迹。配置版本与发布流程在需要审核、回滚或固定执行配置时单独定义。

本方案基于本地源码与交接文档，后端源码及集成测试不在本仓库中。后端、数据库、真实模型、浏览器和生产代理的实际行为以核心联调为准，工期为上述条件下的粗估。
